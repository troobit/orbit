# Peer Review: Shared JSON Design

Reviewed the 18:21Z merged design against approved requirements, decisions, design questions and current repository code. This is same-model fresh-context parallel evidence, **not independent-model evidence from the current critique**. The merge author uses a different harness/model. No critique, cross-review, draft or other review file was read; no private logs or machine data were inspected. Human decisions and U1–U3 remain unchanged.

1. **Major — Kiro heuristics still bypass the streaming exec probe** ([2.1](../../requirements.md#2.1), [5.2](../../requirements.md#5.2)). [Design §2](../../design.md#2-codex-exec-stream-parser) extends detection only when the initial chunk “is not Kiro.” In [detectKiroFormat](../../../../internal/transcript/parser.go), an invalid chunk containing the literal keys `executionId`, `chat` and `metadata` becomes Kiro IDE without structural validation. Put those keys in a malformed prefix longer than 64 KiB, followed by a valid `thread.started`: discovery probes through it and lists the stream, while direct conversion selects Kiro and fails. **Fix:** let the streaming exec probe run before accepting a heuristic Kiro result when no complete object was found; retain Kiro as the fallback. Add this exact false-positive prefix to detection/listing parity tests.

2. **Major — Suppression validates any duplicate rather than the resolver’s winner** ([2.7](../../requirements.md#2.7), [4.2](../../requirements.md#4.2), [5.8](../../requirements.md#5.8)). [Design §5](../../design.md#5-exec-discovery-identity-project-and-suppression)/Decision 17 index every matching rollout head, but [findCodexSession](../../../../internal/sessions/resolver.go) opens the first filename match. An earlier unreadable, empty or mismatched rollout can shadow a later valid matching rollout; that later file still suppresses the usable exec stream. Q49’s listing de-duplication does not prove the indexed file is the one opening will select. **Fix:** share candidate selection between listing, opening and suppression; contribute an ID only when the selected candidate is readable, parseable and records that thread. Test an invalid first duplicate followed by a valid duplicate, in both scopes.

3. **Major — The Claude head limit changes existing listing output** ([5.1](../../requirements.md#5.1)). [Design §4](../../design.md#4-listing-scope-and-cache-sessions) caps Claude extraction at 50 lines/1 MiB. Existing [ParseFirstTimestamp](../../../../internal/transcript/parser.go) scans until the first timestamp, with a 10 MiB per-line limit. A transcript with 50 untimestamped infrastructure entries followed by a timestamp currently lists by recorded time; the new design lists it by modification time and can change `latest` without any new option. **Fix:** preserve the current timestamp scan for existing sources, caching its result; apply bounded reads only to newly extracted optional fields. Add a no-flags compatibility fixture whose first timestamp falls beyond the proposed cap.

4. **Major — Recorded providers disappear without an assistant entry** ([1.1](../../requirements.md#1.1), [1.6](../../requirements.md#1.6), [3.1](../../requirements.md#3.1)). The metadata table derives Codex provider from `session_meta`, but [projection §3](../../design.md#3-shared-json-projection-internalsharedjson) derives document summaries only from entries. The proposed `ParseResultMetadata` has no provider/model fields. A valid rollout containing `session_meta` and only a user message produces no assistant carrying the known provider; direct-file and stdin shared JSON therefore lose it under the projection rule. **Fix:** define first-known parsed session model/provider storage and its precedence with entry values, including sessions without assistant content. Add user-only and empty-content metadata fixtures; retain subsequent changes on entries.

5. **Major — Missing item IDs regain collisions in renderer links** ([1.1](../../requirements.md#1.1), [2.3](../../requirements.md#2.3), [5.7](../../requirements.md#5.7)). [Design §2](../../design.md#2-codex-exec-stream-parser) keys missing-ID records by physical line, but emits every tool link as `t<turn>:<item id>`. Two missing-ID commands in one turn both become `t1:`; transcript-wide renderer maps then associate results with the wrong command. The pinned [item definition](https://raw.githubusercontent.com/openai/codex/rust-v0.166.0/codex-rs/exec/src/exec_events.rs) requires an ID, but missing Go struct fields do not fail typed decoding. **Fix:** either route missing-ID tool shapes to generic events with a warning, or include the physical-line fallback in internal tool IDs while leaving original `item_id` absent. Verify two such commands across all renderers.

Before implementation: which shared candidate function establishes rollout resolvability for duplicates? Where will first-known session metadata survive when no assistant entry exists?
