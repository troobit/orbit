# LM Studio Requirements Critique

Reviewed the requirements, decisions and questions following the **2026-11-04T18:12Z merge completion**. This is a same-harness/model, fresh-context review by `codex-gpt-6.1-sol`, not independent-model evidence. No peer review, other review files or private logs were read. Repository code and public primary documentation supplied the checks.

No critical findings. Three major and two minor findings follow.

1. **Major — Tool links need request scope** ([AC 2.3](../../requirements.md#2.3), [3.5](../../requirements.md#3.5), [4.5](../../requirements.md#4.5), [8.3](../../requirements.md#8.3)). Preserving recorded linking identifiers is insufficient when snapshots repeat tool calls or a direct transcript contains unrelated sessions using the same identifier. Current `BuildToolMeta` in [markdown.go](../../../../internal/transcript/markdown.go) indexes the whole transcript by raw tool ID; `preprocessEntries` in [grouping.go](../../../../internal/transcript/grouping.go) similarly overwrites results and tracks consumed results globally. This can substitute another request's result or suppress content. Require request-scoped internal links, separately retained original identifiers, and renderer grouping that respects request/session boundaries. Test duplicate IDs across snapshots and unrelated sessions, including prefix-referenced history.

2. **Major — The web route to unattributed evidence is undefined** ([AC 1.4](../../requirements.md#1.4), [4.2](../../requirements.md#4.2), [4.5](../../requirements.md#4.5), [7.1](../../requirements.md#7.1), [8.2](../../requirements.md#8.2); Decisions 3/7, U3/U7). Session pages exclude unmatched bodies, while direct log views preserve them; 8.2 nevertheless requires web parity for direct inputs containing multiple sessions. The existing [server routes](../../../../internal/apsisweb/server.go) expose session identifiers, with no direct-file view. A file reference alone does not define how a browser reaches that evidence. Specify a root-confined, all-projects log-file view reachable from references, with locator validation and a missing-file outcome; alternatively state that inspection requires an explicit CLI command and narrow the direct-input web acceptance criterion accordingly. Stdin need not become a web upload feature.

3. **Major — Routine-record filtering overlaps mandatory diagnostic retention** ([AC 4.2](../../requirements.md#4.2), [4.4](../../requirements.md#4.4), [6.2](../../requirements.md#6.2)). 4.2 retains every unattributed WARN/ERROR body in direct views; 4.4 ignores routine startup, model-management, prompt-cache and engine records without conversation content. Such categories can also contain WARN records. The requirements give no precedence, so an implementation can discard a diagnostic while satisfying the category filter. State that WARN/ERROR retention takes precedence and limit routine suppression to other levels. Add synthetic WARN/ERROR records carrying those tags alongside ignored progress records.

4. **Minor — Native chat string input should be explicit** ([AC 2.2](../../requirements.md#2.2), [8.2](../../requirements.md#8.2)). “Typed `input`” leaves the native mapping narrower than the documented `string | array<object>` union. Endpoint coverage alone could pass using only object arrays. Explicitly map a string to supplied user context and require fixtures for both forms, including `system_prompt`. [LM Studio's native chat reference](https://lmstudio.ai/docs/developer/rest/chat) documents both shapes; it does not establish either disk-log form.

5. **Minor — Invalid zone selection has no outcome** ([AC 5.1](../../requirements.md#5.1), [5.2](../../requirements.md#5.2), [8.3](../../requirements.md#8.3); Decision 4/U8). These criteria distinguish bad wall times but not an invalid `TZ` or unavailable zone data. On Unix, Go's [local-zone initialization](https://go.dev/src/time/zoneinfo_unix.go) silently falls back to UTC when loading fails; an empty `TZ` also selects UTC. Using it unchecked can present a failed assumption as a uniquely interpreted time. Define accepted zone syntax, empty-value semantics and a visible invalid-zone outcome that retains wall time without inventing an absolute timestamp; verify the contract across supported platforms.

Unresolved questions before design:

- Will body-free references open a root-confined browser log view, or explicitly direct users to CLI inspection?
- Which internal scope and preserved source-ID fields prevent tool links crossing request boundaries, including repeated prefixes?
- Does WARN/ERROR retention always override routine-record suppression?
- Which `TZ` forms are accepted, and must invalid or unavailable zone data warn while leaving absolute times absent?
