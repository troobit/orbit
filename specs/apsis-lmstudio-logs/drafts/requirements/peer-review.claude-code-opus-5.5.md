# LM Studio Requirements Peer Review (Independent Model)

Reviews the **post-revise 18:21Z revision** (44 criteria, Decisions 9/10, U1–U8). `claude-code-opus-5.5` differs in harness and model family from all earlier reviewers. Checked against repository code, public LM Studio docs, pinned Codex 0.166.0 source and counts-only checks of local server logs; no log content, identifiers, paths or model names are copied. The codex reviews were read after these findings formed.

No critical findings. Four major, six minor.

## Major

1. **Unthreaded requests flood listings** ([3.2](../../requirements.md#3.2), [7.1](../../requirements.md#7.1), [7.2](../../requirements.md#7.2); Decision 1, U2). Locally, 6,182 included-endpoint requests span 79 files; only about 848 carry `client_metadata.thread_id`. About 5,300 singletons become all-projects rows, re-rendered every 15 s by the [web list](../../../../internal/apsisweb/templates/sessions.html). U2 never states this consequence. **Fix:** add U2 options to list unthreaded requests as one entry per log file (requests keep singleton IDs; no shared conversation claimed), or to leave them to direct conversion. Record the consequence in Decision 1; add a listing-volume case to [8.5](../../requirements.md#8.5).

2. **`latest` will usually pick LM Studio** ([7.1](../../requirements.md#7.1), [8.1](../../requirements.md#8.1); sibling 4.4). `latest` picks the newest creation time. A thread session starts at its first request, after its client rollout starts, and other clients keep adding newer singletons, so all-projects `latest` returns server-log views and 8.1 makes `latest -F` fail. [`runLatest`](../../../../cmd/apsis/main.go) already rejects following Kiro CLI, but Kiro sessions don't arrive continuously from unrelated clients. **Fix:** in 7.1, `latest` SHALL NOT select LM Studio sessions unless the source selector names `lmstudio`. Narrow 8.1's `latest` clause to that case.

3. **Shared JSON loses request parameters that raw JSON users are sent to find** ([2.2](../../requirements.md#2.2), [8.1](../../requirements.md#8.1), Non-Goals). 2.2 and 3.7 keep only endpoint, model, location, conversation content and thread ID, so `tools`, `tool_choice`, `stream`, `store`, sampling and `reasoning` settings, `max_output_tokens`, `prompt_cache_key` and other `client_metadata` become unreachable. `stream` explains most missing responses. **Fix:** in 2.2, shared JSON SHALL keep remaining top-level body fields as parsed request parameters, truncation markers intact; Markdown/HTML show at least `stream` and offered tool names. Decide whether [native chat](https://lmstudio.ai/docs/developer/rest/chat)'s `integrations[].headers` values, possibly credentials, are redacted.

4. **Documented and future endpoints vanish silently** ([2.1](../../requirements.md#2.1), [4.4](../../requirements.md#4.4)). The cited [OpenAI-compatible page](https://lmstudio.ai/docs/developer/openai-compat) lists `POST /v1/decisions` (a decision model answering typed questions); 2.1 neither includes nor excludes it, and 4.4 silently drops any new inference path. None occur locally. **Fix:** name it in 2.1 (exclude with a reason, or map `input`/`questions` and `answers`), and require one body-free warning with a count per POST path in neither list.

## Minor

5. **Codex provenance and side requests** ([3.1](../../requirements.md#3.1), [3.7](../../requirements.md#3.7), [8.4](../../requirements.md#8.4)). The pinned [`responses_metadata.rs`](https://raw.githubusercontent.com/openai/codex/rust-v0.166.0/codex-rs/core/src/responses_metadata.rs) is public provenance for `thread_id`; cite it. It sends `thread_id` on every request, including compaction and `memory` requests that Codex's turn metadata marks thread-less. The request kind sits in `x-codex-turn-metadata`, truncated in all 848 local occurrences. **Fix:** Decision 1 should state that side requests join the thread and can trigger [3.6](../../requirements.md#3.6) discontinuities; expose `request_kind` where recorded completely; in 3.7 also keep `x-codex-parent-thread-id` (sub-agent parent).

6. **Detection precedence and failure message** ([1.1](../../requirements.md#1.1)). [`DetectFormat`](../../../../internal/transcript/parser.go) runs Kiro's bare-substring fallback first. A request body with `"executionId"`, `"chat"` and `"metadata"` keys could therefore be read as Kiro IDE. Locally, 36 of 79 files hold no included request, and one file's first request starts beyond 64 KiB. For those files, `apsis <file>` fails with "no format-defining entries found in file". **Fix:** state that LM Studio detection runs before other detectors' substring checks. When the probe finds LM Studio headers but no included request, the error should name `-a lmstudio`.

7. **Windows time zones** ([5.1](../../requirements.md#5.1), [5.5](../../requirements.md#5.5)). [Releases](../../../../.github/workflows/release.yml) include Windows. Go's Windows local zone ignores `TZ`, and nothing in the repository imports `time/tzdata`. IANA names therefore usually fail to load on Windows, so every override there becomes wall-time-only output. The absolute-path form is Unix-only. **Fix:** require embedded tzdata for zone validation, or state the Windows behaviour. Name the `/`-prefixed path form explicitly.

8. **Constant attribution label** ([2.4](../../requirements.md#2.4)). Under 4.1, every request states `no uniquely attributable response logged`, which would repeat about 6,000 times locally. **Fix:** use one transcript-level notice and a per-request JSON state.

9. **Browser CLI instructions** ([4.2](../../requirements.md#4.2), [7.1](../../requirements.md#7.1)). The existing size-limit page in [`handleTranscript`](../../../../internal/apsisweb/handlers.go) suggests `apsis <id>`. That command cannot open an LM Studio session without all-projects scope and the source selector. **Fix:** require every browser CLI instruction to include both.

10. **Direct-file identity** ([3.4](../../requirements.md#3.4)). It is unclear whether logical-session IDs from converting a file under the root equal the listed IDs. **Fix:** say they match for files under the configured root, and are input-scoped like stdin otherwise.
