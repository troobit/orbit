## Technical Choices for Design

These are agent-owned implementation questions, not requests for human approval:

- Specify exact CLI/environment names, identifier derivation and direct-input identity scope.
- Set and document the record-size limit; keep it distinct from the existing 50 MiB web transcript limit and the 65,536-byte detection probe.
- Define the additive schema fields for request boundaries, context provenance, direct-log session membership, unattributed-event references and assumed wall time.
- Define complete request-parameter projection and non-conversation details rendering; no selective credential redaction is proposed. Keep side/parent/request-kind metadata raw when truncated, and document supported complete shapes from pinned sources.
- Qualify tool links within request occurrences or individual logged-response events while retaining original IDs for metadata and history-prefix equality; groups must not cross those boundaries.
- Define cache identity/invalidation and the deletion/replacement path before implementation; no persistent index or cold-time service-level target is admitted.
- Establish synthetic fixture provenance for each named response marker; unsupported or unverified payload shapes must stay generic with warnings. Do not invent request-attribution fields for positive fixtures; the supported grammar has no established request-scoped matcher.
- Name the exact known non-inference path rules and unsupported-POST warning aggregation scope; `/v1/decisions` remains explicitly unsupported rather than silently ignored.
- Supply portable IANA zone data and explicit TZ interpretation independently of the host local-zone API. Choose the binary integration (the standard-library tzdata package is available), native absolute-path validation and tests before implementation.
